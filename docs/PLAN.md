# DragRACE-S 開発計画

授業用の DragRACE とは別に、個人開発用として進めるリポジトリの計画書です。

## 目標

- 将来的に MAGP（Minicar Autonomous Grand Prix）に出場できる車両を作る
- 蛇行したラインをそのままなぞるのではなく、コース幅を使って滑らかに速く走れるようにする（段階的なショートカット）

## 基本方針

- 走行の基本は当面 DragRACE のプログラムをベースにする
- 地図生成には ROS 2（Jazzy）を使う。ROS 2 はラズパイ4（4GB、Raspberry Pi OS 64ビット / Debian 13）上の Docker コンテナで動かし、ラズパイ本体の OS と DragRACE はそのまま残す
- カメラはリボンケーブル接続のため、Docker の中からは扱いにくい。カメラとライントレースは Docker の外の DragRACE で扱う（ライントレースを ROS 2 に移すときに改めて検討）
- Docker の設定一式は docker フォルダにまとめる（使い方は docker/README.md）
- ROS 2 への移行は段階的に行う
  1. Docker 内で LiDAR と地図作りを動かす（走行は DragRACE のまま）
  2. 位置推定を ROS 2 のノードにする
  3. 走行の判断や制御を少しずつノードに移す（どこまで移すかは 1 がうまくいった時点で判断）
- 移行の途中は、DragRACE と ROS 2 の間でデータをやり取りする橋渡しの仕組みを用意する（移行が進めば不要になる）
- 処理が重くなったら、IMU の読み取りやモーター・ステアリング制御など「軽くて速さが大事な処理」をラズパイ Pico などのマイコンに分担する
- 公式ルールは参考程度とし、必要になった時点で合わせる
- ジョイスティックによる手動操作を入れる

## リポジトリ運用

- 本家（RC-DragRACE/DragRACE）は upstream として登録済み。ただし本家はほぼ完成形なので、更新の取り込みは重要視しない
- 機能ごとに作業ブランチを分ける（例：feature/imu、feature/lidar、feature/ros2）
- 編集はノートパソコンで行い、ラズパイ側は git pull で最新版を取得して動かす
- upstream の登録はパソコンごとに必要

## センサー

### IMU

- 機種：AE-LSM6DSV16X（6軸：加速度＋ジャイロ、地磁気なし）
- 接続：ラズパイ4に I2C で直接接続
  - 1番ピン（3.3V）→ 電源、6番ピン（GND）→ GND、3番ピン（SDA）→ SDA、5番ピン（SCL）→ SCL
  - 電源は必ず 3.3V。I2C で使うには CS ピンが 3.3V 側になっている必要がある（モジュール側の処理を要確認）
  - I2C アドレスは 0x6A または 0x6B
- 用途：ヨー角（車の向き）の取得。ハンドル指令に対して実際にどれだけ向きが変わったかのフィードバック、地図作りと自己位置推定の補助
- 注意：ヨー角はジャイロの積算なので時間とともにずれる。チップ内蔵のセンサーフュージョン機能の活用も検討

### LiDAR

- 機種：LDROBOT LD19（DFRobot の dToF LD19 レーザー測距センサキット 12m。2D、測定距離 0.02〜12m、約10Hz、約39×39×34mm と小型）
- 接続：キット付属の変換ボードと USB ケーブルでラズパイ4に USB 接続
- ドライバー：LDROBOT 公式の ldlidar_stl_ros2（Docker の部屋の中でビルド）
- 取り付け：ベースプレート上の低い位置。光の面がダクトの上端より下に来るようにし、水平に取り付ける
- 用途：地図生成と、走行中の自己位置推定の両方

## LiDAR の点の絞り込み（パラメータ）

すべて設定から説明付きで調整できるようにする。

| パラメータ | 役割 | 調整の目安 |
|---|---|---|
| 最大距離 | これより遠い点を捨てる。ダクトのつなぎ目から光が抜けて、コース外の人の足や会場の壁を拾うのを防ぐ | コースの大きさに合わせる。小さくしすぎると遠くの壁まで消える |
| 最小距離 | これより近い点を捨てる。自分の車体やタイヤに当たった点を除く | 車体の大きさに合わせる。大きくしすぎると近くの壁まで消える |
| 無視する角度の範囲 | 後部ボックスや支柱で隠れる方向をまとめて無視する | 複数指定できるようにする |
| 間引きの間隔 | 何点に1点を使うか | ラズパイ4の処理が重いときに増やす。増やしすぎると精度が落ちる |

## 動作モード

### 地図作りモード

- サーボ・スロットルの調整と同じく、別枠のモードとして用意する
- 地図作りは ROS 2 の既存ツールで行う
- ゆっくりのライントレースで1周走り、地図を作る（ゆっくり・なめらかに走るほど地図の精度が上がる）
- 地図は ROS 2 の標準形式（画像＋設定ファイル）で保存し、DragRACE 側の画面表示からも読めるようにする
- 地図だけでなく LiDAR の生データも保存する（後でループ閉じ込みなどを改善したときに、走り直さずに地図を作り直せるように）
- 保存先は maps フォルダ。会場ごとに名前を付けて保存し、走行時に選べるようにする
- 地図ファイルは Git に含めない（.gitignore に追加）
- 地図を作り始めた場所と同じ場所から走行を始める決まりにする（最初の位置合わせを簡単にするため）

### 走行モード

- 保存した地図を読み込み、LiDAR と IMU で地図上の自己位置を推定して走る
- 自己位置を見失ったらライントレースに切り替え、走りながら位置を推定し直す

### 画面表示

- DragRACE の画面に、地図・現在位置・走った軌跡を重ねて表示する
- デバッグにも使う

## 開発の段階

1. リポジトリ準備（完了）。ラズパイ4に Docker を導入し、ROS 2 Jazzy の動作確認（完了）
2. IMU 導入：配線、I2C 有効化、ヨー角の取得
3. ジョイスティックによる手動操作
4. LiDAR 導入：機種選定、取り付け、点の絞り込みパラメータ
5. ラズパイ4に Docker と ROS 2 の環境を作り、コンテナ内から LiDAR・IMU を使えるようにする
6. 地図作りモード（ROS 2）と、DragRACE との橋渡し
7. 自己位置推定（ROS 2 ノード。見失ったときのライントレース切り替えを含む）
8. 画面表示（地図・現在位置・軌跡）
9. 走行の判断・制御のノード化をどこまで進めるか判断し、移行
10. 最適経路の生成と追従（ショートカット）
11. 改善：ループ閉じ込み、エンコーダー（車輪速）、マイコンへの処理分担
