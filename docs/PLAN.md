# DragRACE-S 開発計画

授業用の DragRACE とは別に、個人開発用として進めるリポジトリの計画書です。

## 目標

- 将来的に MAGP（Minicar Autonomous Grand Prix）に出場できる車両を作る
- 蛇行したラインをそのままなぞるのではなく、コース幅を使って滑らかに速く走れるようにする（段階的なショートカット）

## 基本方針

- 走行の基本は当面 DragRACE のプログラムをベースにする
- 地図生成には ROS 2（Jazzy）を使う。ROS 2 はラズパイ4（4GB、Raspberry Pi OS 64ビット / Debian 13）上の Docker コンテナで動かし、ラズパイ本体の OS と DragRACE はそのまま残す
- カメラはリボンケーブル接続のため、Docker の中からは扱いにくい。カメラとライントレースは Docker の外の DragRACE で扱う（ライントレースを ROS 2 に移すときに改めて検討）
- Docker の設定一式は docker フォルダにまとめる（使い方は docker/README.md）
- ROS 2 への移行は段階的に行う
  1. Docker 内で LiDAR と地図作りを動かす（走行は DragRACE のまま）
  2. 位置推定を ROS 2 のノードにする
  3. 走行の判断や制御を少しずつノードに移す（どこまで移すかは 1 がうまくいった時点で判断）
- 移行の途中は、DragRACE と ROS 2 の間でデータをやり取りする橋渡しの仕組みを用意する（移行が進めば不要になる）
- 処理が重くなったら、IMU の読み取りやモーター・ステアリング制御など「軽くて速さが大事な処理」をラズパイ Pico などのマイコンに分担する
- 公式ルールは参考程度とし、必要になった時点で合わせる
- ジョイスティックによる手動操作を入れる

## リポジトリ運用

- 本家（RC-DragRACE/DragRACE）は upstream として登録済み。ただし本家はほぼ完成形なので、更新の取り込みは重要視しない
- 機能ごとに作業ブランチを分ける（例：feature/imu、feature/lidar、feature/ros2）
- 編集はノートパソコンで行い、ラズパイ側は git pull で最新版を取得して動かす
- upstream の登録はパソコンごとに必要

## センサー

### IMU

- 機種：AE-LSM6DSV16X（6軸：加速度＋ジャイロ、地磁気なし）
- 接続：ラズパイ4に I2C で直接接続
  - 1番ピン（3.3V）→ 電源、6番ピン（GND）→ GND、3番ピン（SDA）→ SDA、5番ピン（SCL）→ SCL
  - 電源は必ず 3.3V。I2C で使うには CS ピンが 3.3V 側になっている必要がある（モジュール側の処理を要確認）
  - I2C アドレスは 0x6A または 0x6B
- 用途：ヨー角（車の向き）の取得。ハンドル指令に対して実際にどれだけ向きが変わったかのフィードバック、地図作りと自己位置推定の補助
- 注意：ヨー角はジャイロの積算なので時間とともにずれる。チップ内蔵のセンサーフュージョン機能の活用も検討
- 動作確認（2026-11-07）：I2C アドレス 0x6B、WHO_AM_I = 0x70。確認スクリプトは tools/imu_test.py
  - 静止時のジャイロのずれ：約 gx −0.35、gy −0.06、gz −0.76 °/s（起動時に 2 秒間測って差し引く）
  - 取り付けの傾き：0.5° 未満（水平）
- 取り付け向き（実測で確認）
  - センサーの Z ＝ 車の上
  - センサーの −Y ＝ 車の前（フロントを持ち上げると Y がマイナスに変化）
  - センサーの X ＝ 車の左
  - ヨー角は反時計回り（左旋回）がプラス。ROS 2 の標準（REP 103）と同じ向き
  - 車の座標への変換：前 ＝ −Y、左 ＝ +X、上 ＝ +Z（ROS 2 の取り付け設定ではヨー +90°）
  - 台座は付け替えるときも同じ向きにする

### LiDAR

- 機種：LDROBOT LD19（DFRobot の dToF LD19 レーザー測距センサキット 12m。2D、測定距離 0.02〜12m、約10Hz、約39×39×34mm と小型）
- 接続：キット付属の変換ボードと USB ケーブルでラズパイ4に USB 接続
- ドライバー：LDROBOT 公式の ldlidar_stl_ros2（Docker の部屋の中でビルド）
- 取り付け：ベースプレート上の低い位置。光の面がダクトの上端より下に来るようにし、水平に取り付ける
- 用途：地図生成と、走行中の自己位置推定の両方
- 動作確認（2026-11-07）：/dev/ttyUSB0 で認識、/scan は約 10Hz、1 周あたり約 585 点（約 0.62° 間隔）
  - 起動コマンド：`ros2 launch ldlidar_stl_ros2 ld19.launch.py`
  - ドライバーが 2 つ同時に動くとスキャンが約 7Hz に落ちて途切れる。起動前に `pkill -f ldlidar` で止めておく
  - モーターは電源が入ると回り続ける（PWM 線が未接続のため）。止めたい場合はスイッチ付き USB ケーブル、または PWM 線を GPIO につないで制御
- 取り付け向き（実測で確認）
  - 0° ＝ ほぼ車の前（真正面の箱が 358° に出た。約 2° 左に回った状態で付いている）
  - 角度は反時計回りに増える（ROS 2 の標準と同じ。IMU のヨー角とも同じ向き）
- 車体による遮り（40cm 以内にある物、実測）
  - 約 160°（16cm）・約 195°（15cm）：マウントの足 2 本
  - 約 176〜178°（14〜15cm）：真後ろのリボンケーブルかカメラ台
  - 約 183〜185°（9cm）：LD19 自身のケーブル
  - 約 167°（25cm、ときどき）：ラズパイ上のジャンパー線か後ろの柱
  - → **無視する角度の範囲は 150°〜210°**（余裕込み）。使える範囲は 300°

### センサーの取り付け位置（2026-11-07 実測、おおよその値）

基準点（base_link）は、後輪の車軸の中心の真下の床。前が +x、左が +y、上が +z（ROS 2 の標準）。
横方向はどちらも車の中央に配置したので 0 とする。

| センサー | 前 x | 横 y | 高さ z | 向き（ヨー） | ROS 2 のフレーム名 |
|---|---|---|---|---|---|
| LD19 | 0.225 m | 0 m | 0.115 m | +2°（0.035 rad、当面は 0 でも可） | base_laser |
| IMU | 0.170 m | 0 m | 0.037 m | +90°（1.571 rad） | imu_link |

- この値を ROS 2 の取り付け設定（static transform）に書くと、2 つのセンサーのデータを正しく重ねられる
- 取り付けを変えたら測り直してここを更新する

## LiDAR の点の絞り込み（パラメータ）

すべて設定から説明付きで調整できるようにする。

| パラメータ | 役割 | 調整の目安 |
|---|---|---|
| 最大距離 | これより遠い点を捨てる。ダクトのつなぎ目から光が抜けて、コース外の人の足や会場の壁を拾うのを防ぐ | コースの大きさに合わせる。小さくしすぎると遠くの壁まで消える |
| 最小距離 | これより近い点を捨てる。自分の車体やタイヤに当たった点を除く | 車体の大きさに合わせる。大きくしすぎると近くの壁まで消える |
| 無視する角度の範囲 | 後部ボックスや支柱で隠れる方向をまとめて無視する | 複数指定できるようにする |
| 間引きの間隔 | 何点に1点を使うか | ラズパイ4の処理が重いときに増やす。増やしすぎると精度が落ちる |

## 動作モード

### 地図作りモード

- サーボ・スロットルの調整と同じく、別枠のモードとして用意する
- 地図作りは ROS 2 の既存ツールで行う
- ゆっくりのライントレースで1周走り、地図を作る（ゆっくり・なめらかに走るほど地図の精度が上がる）
- 地図は ROS 2 の標準形式（画像＋設定ファイル）で保存し、DragRACE 側の画面表示からも読めるようにする
- 地図だけでなく LiDAR の生データも保存する（後でループ閉じ込みなどを改善したときに、走り直さずに地図を作り直せるように）
- 保存先は maps フォルダ。会場ごとに名前を付けて保存し、走行時に選べるようにする
- 地図ファイルは Git に含めない（.gitignore に追加）
- 地図を作り始めた場所と同じ場所から走行を始める決まりにする（最初の位置合わせを簡単にするため）

### 走行モード

- 保存した地図を読み込み、LiDAR と IMU で地図上の自己位置を推定して走る
- 自己位置を見失ったらライントレースに切り替え、走りながら位置を推定し直す

### 地図作り専用プログラム map_test.py（2026-11-17 決定）

- servo_test.py などと同じく `python3 map_test.py` で起動し、専用のブラウザ画面で地図作りを行う
- 地図作り中は、map_test.py の中でゆっくりライントレースして 1 周する（rc_race.py のライン検出・ハンドル制御を流用）
- 設計の詳細は docs/MAP_TEST.md、画面イメージは docs/images/map_test_ui.png

### ライントレースの新方式（2026-11-17 検討）

- 今の方式（近くの帯のズレに P・D 制御）と切り替えられる形で、ピュアパシュートを追加する
- シミュレーションで 7 方式を比べ、「先読み距離を速度で変えるピュアパシュート＋横向きのラインも追える点群検出」を採用候補にした。比較の詳細と実装の順番は docs/LINETRACE_EVAL.md、シミュレーションは tools/linetrace_sim/
- 切り替えは kuruma_settei.json の `LINE_ALGO`（"pd"＝今の方式、"pp"＝ピュアパシュート）
- カメラだけで走れる上限は 3 m/s あたりの見込み。それ以上は地図で先のカーブを知る必要がある
- 実装済み（2026-11-17）：line_algo.py（部品）、pp_test.py（キャリブレーションと確認の画面）、rc_race.py の切り替えと見るだけモード。使い方は docs/PP_TEST.md。**実機での確認はこれから**

### コースの切り替え（2026-11-07 決定）

- 1 つのコース ＝ maps フォルダの `<コース名>.png`・`.yaml`・`.pbstream` の 3 つのファイル
- 普段は同じコースを使い続ける。コースが変わったら新しい名前で地図を作り直す
- どのコースを使うかは、map_test.py の画面の「保存済みのコース」から選ぶ。選んだ名前は kuruma_settei.json の `COURSE_NAME` に書かれ、rc_race.py がそれを使う（初期値は最後に選んだコース）
- 打ち込んだ名前のファイルがない場合は、画面に警告を出してライントレースだけで走る

### 画面表示

- rc_race.py と各テスト用プログラム（servo_test.py など）のブラウザ画面に、地図・現在位置・走った軌跡を重ねて表示する
- デバッグにも使う
- 実現に必要なもの：①走行中の位置推定（Cartographer の位置推定モード、.pbstream を使う）、②ROS 2 から DragRACE へ現在位置を渡す橋渡し、③ブラウザ画面への描画

## 開発の段階

1. リポジトリ準備（完了）。ラズパイ4に Docker を導入し、ROS 2 Jazzy の動作確認（完了）
2. IMU 導入：配線、I2C 有効化、ヨー角の取得
3. ジョイスティックによる手動操作
4. LiDAR 導入：機種選定、取り付け、点の絞り込みパラメータ
5. ラズパイ4に Docker と ROS 2 の環境を作り、コンテナ内から LiDAR・IMU を使えるようにする
6. 地図作りモード（ROS 2）と、DragRACE との橋渡し
7. 自己位置推定（ROS 2 ノード。見失ったときのライントレース切り替えを含む）
8. 画面表示（地図・現在位置・軌跡）
9. 走行の判断・制御のノード化をどこまで進めるか判断し、移行
10. 最適経路の生成と追従（ショートカット）
11. 改善：ループ閉じ込み、エンコーダー（車輪速）、マイコンへの処理分担
